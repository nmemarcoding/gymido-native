# gymido-native

Gymido member app (with trainer workspace) for iOS and Android. React Native + Expo (dev client, Continuous Native Generation), plain JavaScript.

Admin functionality is web-only and out of scope for this app.

## Stack

| Layer | Choice |
|---|---|
| Framework | Expo SDK 57 / React Native 0.86, dev client (not Expo Go) |
| Language | JavaScript |
| Navigation | React Navigation 7 (native stack) |
| State | Zustand |
| HTTP | Axios (`src/shared/api/client.js`) |
| Preferences | MMKV (`src/shared/storage/preferences.js`) |
| Tokens | Auth0 Credentials Manager (Keychain / Keystore) — never MMKV or AsyncStorage |

App identifier on both platforms: **`com.gymido.app`**.

## Prerequisites

- **Node 24 LTS** (see `.nvmrc`)
- **iOS:** Xcode 26+ with an iOS Simulator runtime, CocoaPods (`brew install cocoapods`)
  - Xcode must be the active developer directory: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`
    (or export `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` in your shell)
- **Android:** Android SDK (platform 36, build-tools 36, emulator) and an AVD, **JDK 17**
  - `ANDROID_HOME` pointing at the SDK (e.g. `~/Library/Android/sdk`)
  - `JAVA_HOME` pointing at JDK 17 — newer JDKs are not supported by the Android build
- Optional: Watchman (`brew install watchman`)

## Setup

```bash
npm install
cp .env.example .env.development   # then fill in values
```

### Environment files

`app.config.js` reads `.env.<APP_ENV>`, where `APP_ENV` is `development`, `staging` or `production` (set by the npm scripts, defaults to `development`). Values are exposed to the app through `src/shared/config/env.js`.

| Variable | Purpose |
|---|---|
| `API_BASE_URL` | Gymido backend API base URL |
| `AUTH0_DOMAIN` | Auth0 tenant domain |
| `AUTH0_CLIENT_ID` | Auth0 **Native** application client ID |
| `AUTH0_AUDIENCE` | Auth0 API audience |

All `.env.*` files except `.env.example` are gitignored. Everything in them is compiled into the app binary, so **never put secrets in them** — a native app has no client secret.

## Running

The app uses a dev client, so the first run (and any run after adding a native dependency or changing `app.config.js`) needs a native build:

```bash
npm run ios        # build + launch on the iOS Simulator, starts Metro
npm run android    # build + launch on an Android emulator/device, starts Metro
```

After the native app is installed, you only need Metro for JS changes:

```bash
npm start                  # development env
npm run start:staging      # staging env
npm run start:production   # production env
```

To target a specific device: `npx expo run:ios --device "iPhone 17 Pro"` or `npx expo run:android --device <AVD name>`.

### Native folders

`ios/` and `android/` are generated by `expo prebuild` and are **not committed**. Native configuration belongs in `app.config.js` (and config plugins), never in hand-edits to those folders. To regenerate from scratch:

```bash
npm run native:clean
```

## Scripts

| Script | Does |
|---|---|
| `start`, `start:staging`, `start:production` | Metro for the dev client with that env |
| `ios`, `android` | Native build + launch (development env) |
| `native:clean` | Regenerate `ios/` and `android/` |
| `doctor` | `expo-doctor` dependency/config checks |

## Project structure

```
index.js                 # registers src/App
app.config.js            # Expo config + env loading
assets/                  # app icon, splash, adaptive icon
src/
  App.js                 # providers + NavigationContainer
  features/              # one folder per feature area (auth, home, bookings, profile, trainer, ...)
  navigation/            # navigators, route names, route guards
  shared/
    api/                 # Axios client
    components/
    config/              # runtime env
    hooks/
    storage/             # MMKV preferences (never tokens)
```

Code is organised by feature, not by file type.
